# Source and claims policy

SEO changes faster than a static skill file. Use this hierarchy when validating claims.

## Preferred source hierarchy

1. Search-engine primary documentation and status pages.
2. Standards/specifications such as Schema.org, robots.txt/sitemaps standards, HTTP, HTML.
3. Field data from the user's own Search Console, analytics, CrUX/RUM, logs, and rank tracking.
4. Reputable testing/research that shows methodology and date.
5. Community observations only as hypotheses until independently verified.

## Primary sources to prefer

For Google: Google Search Central and web.dev. Verify current documentation for Search Essentials, spam policies, crawling/indexing, canonicalization, robots directives, sitemaps, JavaScript SEO, structured data, title links/snippets, internationalization, Core Web Vitals, and AI features.

For Bing: Bing Webmaster documentation and IndexNow documentation.

For structured data semantics: Schema.org, then the search engine's feature-specific eligibility documentation.

## Claims discipline

Use these labels mentally or explicitly:

- **Verified:** directly supported by current primary documentation or the user's own data.
- **Observed:** directly seen in the site/repo/SERP, but causality is not proven.
- **Likely:** strong technical/SEO inference from evidence.
- **Experimental:** plausible tactic with uncertain or engine-specific impact.
- **Unsupported:** do not recommend as fact.

Never present correlation as a confirmed ranking factor.

## Freshness checks

Re-verify before making strong current claims about:

- rich-result eligibility and deprecated schema features;
- AI Overviews, AI Mode, answer-engine inclusion, crawler controls;
- Core Web Vitals definitions/thresholds;
- spam-policy wording or enforcement categories;
- IndexNow/search submission behavior;
- product/merchant/search appearance features;
- new crawler user agents or controls.

When live verification is impossible, say the rule is based on the bundled baseline and may need a current-doc check.
